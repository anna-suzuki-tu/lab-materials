LAB OS — CHAPTER 05

論文タイプ｜信念のスコープと形式

Paper Types — 信念の形式は複数ある。問いと貢献のスコープから選ぶ

論文タイプは「格」ではない。信念のスコープが違うだけ

論文は成果ではありません。信念に対する説明責任の装置です（01章）。信念のスコープや目的によって、適切な形式は異なります。Original / Review / Technical / Short / Case Study / Perspective——これらは横並びで、上下関係はありません。同じ「信念」を、どのズームレベルで固定するかの違いです。「Original が偉くて Short は格下」という発想を、まず捨ててください。

研究フェーズによって、出す論文タイプは変わる

どのタイプを書くかは、研究がどのフェーズにあるかで大きく決まります。

研究フェーズ状態典型的な論文タイプ
仮説探索期問いは立ったが、主張はまだ小さいShort / Technical — 小さく固定する
仮説安定期主張が図で支えられるOriginal — 新しい主張を出す
軸確立期複数の論文を束ねる研究軸があるReview / Perspective — 問いを再設計し、立場を示す

博士は軸を持つ。その一つの形が Review です。Thesis は枚数ではなく、Paper 1 → Paper 2 → Paper 3 をつなぐ一貫した信念体系です（第9章）。

フェーズを見誤ると、探索期に Original を書こうとして図が足りずに止まるか、安定期に Short を書いて主張を切り売りすることになります。

問いと貢献から、タイプが決まる

03章の Core Question と04章の Key Contributions が決まっていれば、タイプはほぼ自動的に決まります。

タイプ貢献の数とスコープ主図の目安問いとの関係
Original2〜3、分野の信念を更新する3枚前後Core Question に正面から答える
Short / Letter1、限定的だが鋭い1〜2枚Core Question の一部、または強い比較軸1つ
Technical / Method手法そのものが貢献手法の性能と適用範囲「どう測るか・どう解くか」が問い
Case Study / Field Report1〜2、特定条件下条件と結果Core Question を特定ケースで検証
Review分野の Field Belief を書き換える構造図Framing-A 全体が貢献
Perspective立場と方向性概念図次の Core Question を提案する

1 原著論文｜Original Research Article

  • 目的：新しい主張（Claim）を、データや理論で支える
  • 必須：Core Question（1文）／Compared to X, we Y／Key Contributions 2〜3／1図＝1主張の構造／再現可能な方法
  • 典型的なスコープ：新規仮説、新規データ、新規理論、既存理解の修正
  • よくある失敗：データが主役になる／「We propose…」で終わる／新規性を誇張する
  • いつ選ぶか：仮説が安定し、図で主張できる構造が整ったとき

2 ショートコミュニケーション｜Short Communication / Letter

  • 目的：限定的だが鋭い主張を提示する
  • 必須：1つの明確な問い／貢献1つ／1〜2図／強い比較軸
  • よくある失敗：スコープが広すぎる／中途半端な原著になる
  • いつ選ぶか：主張が限定的だが明確なとき。最初の論文の訓練としても有効

3 テクニカルノート／手法論文｜Technical Note / Method Paper

  • 目的：新しい手法・装置・解析法を提示する
  • 必須：何が可能になったか／既存手法との差／適用範囲と限界
  • 重要：「We propose…」で終わらない。何が改善・変化したかを示す（04章の "We show that…"）
  • よくある失敗：技術自慢になる／実装の苦労話になる／応用価値が不明確
  • いつ選ぶか：方法そのものが主張の中心であるとき

4 ケーススタディ／フィールド報告｜Case Study / Field Report

  • 目的：特定条件下での検証を行う
  • 必須：条件の明示／一般化の限界／なぜそのケースが重要か
  • よくある失敗：一般化を過剰に主張する／条件依存を曖昧にする
  • いつ選ぶか：一般化の前に、一つのフィールドで確かめる価値があるとき

5 レビュー論文｜Review Article

  • 目的：分野の信念構造を整理し、問いを再設計する
  • 必須：分野の問いの型／未解明の Gap／構造的整理（単なるまとめではない）
  • 典型的なスコープ：問いの再定義、研究潮流の構造化、今後の方向性提示
  • よくある失敗：ただの文献まとめ／批判性がない／立場が曖昧
  • いつ選ぶか：研究軸が明確になり、分野全体を俯瞰できる段階（主に PhD 後半以降）。D1 は Narrative / Scoping Review から

6 パースペクティブ／論説｜Perspective / Commentary

  • 目的：研究の方向性や立場を提示する
  • 必須：明確な立場／根拠／既存構造との対比
  • よくある失敗：根拠のない意見になる／既存の議論を踏まえていない
  • いつ選ぶか：研究軸が確立し、分野に対する視座を持てたとき

形式から選ぶな。問いから選べ

Question → Format → Venue

  1. Question — まず問い。Core Question と Key Contributions が決まっている
  2. Format — 問いと貢献のスコープに合うタイプを選ぶ（上の表）
  3. Venue — 最後に発表の場を決める。学会か雑誌か、どの雑誌か。場の選び方と投稿の実務は Lab Forum Lectures「Writing Papers」、時期の目安は Notion Lab OS「年間の節目」

「あの学会に出したいから、こういう論文を書く」——順番が逆だと、だいたい迷います。

選ぶときの4つの問い：自分の Core Question は何か／貢献はいくつあり、スコープはどれくらいか／図で支えられるか／比較対象は明確か。

論文タイプを選ぶことは、自分の信念のスコープを決めることです。

著者・誠実さ・再現性の原理は06 研究の責任で、投稿実務は Lab Forum Lectures「Writing Papers」で扱います。
この章のまとめ：論文タイプに序列はなく、信念のスコープが違うだけ ／ フェーズに応じてタイプを使い分ける（探索期 Short・Technical → 安定期 Original → 軸確立期 Review・Perspective）／ 貢献の数とスコープがタイプを決める ／ 選ぶ順番は Question → Format → Venue
