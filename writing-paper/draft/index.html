LAB FORUM — WRITING PAPERS ｜ DRAFT

図を文章にする

Draft — イントロから書かない。Methods から書き、Abstract で閉じる
Results は「何が起きたか」、Discussion は「それが何を意味するか」。Introduction が「不足の宣言」なら、Discussion は「更新の宣言」。鏡になっていなければ、構造は崩れている。

この資料で学べること

Lab Forum Lectures「Writing Papers」は投稿の全体像を、「Writing Papers — Figures」は図の設計を扱いました。このページは、図が確定してから原稿が完成するまで——Paper Card の Draft-A から Draft-I まで——を扱います。

前提は二つ。Figures-C で図が凍結されていること。Framing-A・B で Core Question と Key Contributions が固定されていること。この二つがあれば、Draft は白紙から書く作業ではなく、決まっている材料を文章に展開する作業です。

第1幕
イントロから書かない
書く順序 — 読む順序と書く順序は違う

書く順序

Methods → Results → Discussion → Introduction → Conclusion → Abstract → Polish

原稿は、読む順序と書く順序が違います。読者は Abstract → Introduction → … の順に読みますが、書き手は逆から書きます。

理由は単純で、Introduction は「この論文が何を示したか」を知らないと書けないからです。Introduction の末尾には "Here we show that…" が来ます。それは Discussion の最初の文と一致していなければならない。Discussion を書く前に Introduction を書くと、示していないことを予告するか、示したことを予告し損ねるか、どちらかになります。

Methods から書くのは、そこが最も「事実」に近く、最も迷わないからです。書けないときは、書ける場所から書く。Writing Papers で述べた「白紙の不安には Figure 1 のキャプションから」も同じ原理です。

書けないときは、書ける場所（Methods）から書く。

最重要原則：鏡構造

Introduction と Discussion は鏡である

Introduction と Discussion は鏡です。Introduction が「分野はここまで知っていて、ここが不足している（Gap）」と宣言し、Discussion が「この結果で Gap はこう埋まり、分野の前提はこう更新される」と宣言する。Introduction で宣言した不足が Discussion で回収されていなければ、論文の構造は崩れています。

Results と Discussion の役割分担も同じくらい重要です。Results は「何が起きたか」だけ。Discussion は「それが何を意味するか」だけ。この二つが混ざると、読者は事実と解釈を区別できなくなり、査読者は「Overclaiming」と書きます。

Introductionの不足宣言がDiscussionで回収されているか、常に確認する。
第2幕
事実の土台
Methods と Results

Draft-A｜Methods：他人が再現できる形で

Methods の目的は、他人が再現できる事実の土台を書くことです。Lab OS 06章の「再現性」を、文章として実装する場所です。

4つのブロック

1
Study Design
何を、どの条件で、何と比較し、どんな制約のもとで調べたか。"We designed a study to examine …"
2
Data / Materials
データの出所、サンプル数、期間、選択基準。"Data were obtained from … The dataset includes …"
3
Model / Procedure
手順を Step 1, 2, 3 で。"We applied … The workflow consists of:"
4
Evaluation
評価指標と不確実性の扱い。"Performance was evaluated using … We quantified uncertainty by …"

「詳細は省略」は再現性の放棄です。逆に、修士論文の Methods をジャーナルに再利用するときは出典を引用すれば認められます（Writing Papers の自己盗用の表）。Methods は、論文の中で唯一「型どおりに書いてよい」場所です。

Methodsは唯一「型どおりに書いてよい」場所。

Draft-B｜Results：解釈しない

Results の目的は、図と対応する事実だけを書くことです。

  • 図ごとに結果を書く。Fig.1 → Result 1、Fig.2 → Result 2。1対1
  • 評価語を入れない。「良い」「優れた」「顕著な」は Results に居場所がない
  • "suggests" を使わない。示唆は Discussion の仕事

書く型："Figure 1 shows … X increased as … The difference between A and B was …" 数値、信頼区間、比較の方向を入れます。

Results で「なぜそうなるか」を書きたくなったら、それは Discussion の Direct Answer か Assumption Refinement に移します。Results で一言でも解釈が混ざると、読者は以後の事実を解釈込みで読むようになります。

Resultsは事実だけ。「なぜ」はDiscussionへ移す。
意味を与える5つの段落
Discussion

Discussion：5つの段落

Discussion の目的は、Core Question に答え、結果に意味（分野の信念の更新）を与えることです。5つの段落を、この順で書きます。順序は Framing-A の出力（Core Question、Gap、Hidden assumption、Why it matters）を逆にたどる形になっています。

1｜Direct Answer：問いに直接答える

Core Question をコピーし、それに1〜2文で直接答えます。結果の要約を簡潔に、数字を入れてもよい。ここで解釈を広げすぎない。"This study shows that … Our results indicate that …"

この段落の最初の文が、Introduction の "Here we show" と Conclusion の最初の文になります。3箇所で同じことを言う。ずれていたら論文の主張が定まっていません。

2｜Gap Resolution：Gap を回収する

Introduction の Gap 文を読み直し、「何が足りなかったか」を明示し、今回の結果でどう埋まったかを書きます。新しい Gap をここで作らない。"Our findings address the limitation that … This resolves the uncertainty regarding …"

3｜Assumption Refinement：前提を更新する

既存研究の前提を1つ書き、それがどう変わるかを書きます。「否定」ではなく「更新」で書く。攻撃的な書き方は、査読者に前提を持っている人がいる可能性を考えれば、得がありません。"This challenges the assumption that … Instead, our results suggest that …"

Framing-A の Comparison Table の Hidden assumption と Our update が、そのままこの段落の材料です。

4｜Field Implication：分野への意味

Introduction の冒頭（Broad Context）を読み直し、その文脈がどう変わるかを書きます。理論・応用・設計のどこに影響するかを明示する。世界を救わない。"These findings change how we understand … This has implications for …"

Lab OS 02章のコミットメントがここで効きます。説明にコミットした論文なら理解への含意、制御にコミットした論文なら設計への含意。自分の証拠が届かない含意を書かない。

5｜Limitations：限界と次の問い

本研究の制約を2〜3個書き、それが結果にどう影響するかを書き、次の研究方向を示します。防御的にならない。"This study assumes … One limitation is … Future work should …"

限界を正直に書いた論文の方が査読に耐えます。ズレ（縮められる不確実性）とわからなさ（縮められない不確実性）を分けて書けると、Limitations は弱点の告白ではなく、次の探究への橋になります。

限界を正直に書いた論文の方が、査読に耐える。

Discussion Check

1
Core Question に直接答えているか
2
Gap を回収しているか
3
Context が更新されているか
4
Discussion で初めて出てくる図や結果はないか
第4幕
鏡として逆算する
Introduction

Draft-D｜Introduction：Discussion の後に書く

Introduction の目的は、Discussion で確定した暫定信念を、分野の文脈に正しく配置することです。Lab OS 04章の Narrative Skeleton は、データが出る前に書いた設計図でした。ここでは Discussion を確定させたうえで、それを書き直します。

5つの要素

1
Broad Context（1〜2文）
分野の大きな問いと、なぜ重要か。専門外でも意味がわかる導入。"Understanding X is important because …"
2
Field Context（2〜3文）
支配的なモデル・前提。何が「当たり前」とされているか。詳細レビューにしない。"Previous studies have assumed that … Most existing approaches focus on …"
3
Gap（1文）
不足の宣言。手法も結果も書かない。"However, it remains unclear whether …"
4
Core Question（1文）
Yes/No で終わらない。結果を匂わせない。"This study asks: How does … ?"
5
Contribution Preview（1文）
"Here, we show that …" Discussion の最初の文と一致させる

Introduction Check

1
Gap は Discussion で回収されているか
2
Contribution Preview は Discussion と一致しているか
3
新しい主張を追加していないか

Introduction で新しい主張が増えるのは、書いているうちに「これも言える」と思うからです。言えるなら Discussion に戻して段落を足す。Discussion にないことを Introduction で予告しない。

Discussionにないことを、Introductionで予告しない。
第5幕
圧縮
Conclusion と Abstract

Draft-E｜Conclusion：3段落以内

1
Restated Contribution
Discussion の最初の文を要約する。数値は入れてよい。新情報は入れない。"This study demonstrates that …"
2
Field-Level Meaning
この結果が前提をどう変えるか。2〜3文。過大主張しない。"These findings refine the understanding of … This suggests that …"
3
Forward Look
限界を踏まえた次の問い。「未来は明るい」のような抽象語を使わない。1〜2文。"Future work should …"

Check：Results の繰り返しになっていないか／Discussion のコピーになっていないか／過大主張していないか

Draft-F｜Abstract：6〜7文、順序は固定

1
Background（1文）
Broad Context を1文に。専門語を減らす
2
Gap（1文）
"However, it remains unclear whether …"
3
Question（1文）
"This study investigates …"
4
Method（1文）
"We developed / applied …"
5
Results（2文）
"We found that … Specifically, …" 数値と方向を書く
6
Implication（1文）
"These findings suggest that …"

Check：Introduction と一致しているか／Discussion と一致しているか／新情報を含んでいないか／200〜250 words 以内か

Abstract だけ読んで主張がわかる状態が合格です。多くの読者は Abstract しか読みません。査読者もまず Abstract で論文の主張を固定し、それが本文で支えられているかを見ます。

多くの読者はAbstractしか読まない。それだけで主張が伝わるか。
第6幕
査読耐性
完成と磨き

Draft-G｜Structural Audit

全セクションが揃ったら、構造を監査します。

  • 各 Figure は Contribution を支えているか
  • Results と Discussion が混ざっていないか
  • Introduction と Discussion が鏡構造か
  • 不要な Figure はないか
  • Appendix に逃がすべき内容は何か

想定 Reviewer コメント

査読者が書くコメントは、驚くほど似ています。

1
Novelty is unclear
新規性がどこにあるか不明。Compared to X, we Y が Introduction に見えていない
2
Comparison is insufficient
比較が足りない。Comparison Table の Prior study が本文で比較されていない
3
Assumptions are unrealistic
前提が非現実的。Methods で仮定と適用範囲を書いていない
4
Overclaiming
主張が証拠を超えている。Results の事実と Discussion の含意がコミットメントを跨いでいる

4つとも、Paper Card の Framing と Figures の段階で潰せるものです。投稿前に、この4つを自分で書き、それぞれへの答えが原稿のどこにあるかを指差せるようにします。

投稿前に、この4つへの答えを指差せるようにする。

Draft-H｜全文：荒くてよい

主張が一通り読める原稿を作ります。頭から書かない、完璧を目指さない、英語の細かさを気にしすぎない、Reviewer 対応を考えすぎない。Writing Papers で述べた「生成と編集を分ける」を、原稿全体で実行する段階です。コメントが欲しい点を明示して、Team Meeting か指導教員に渡します。

Draft-I｜磨き：いつまでも磨かない

査読に耐える最小限の完成度を目指します。削れる部分を削る。想定 Reviewer コメントへの答えを書く。Appendix に逃がす内容を決める。

いつまでも磨き続けない。完璧な英語表現よりロジックのクリアさを優先する。一文ずつの点検には Writing Paper Skills の5項目（主張の強さ・査読者の突っ込み・根拠との対応・比較の妥当性・安全な書き換え）を使います。

完璧な英語より、ロジックのクリアさを優先する。

主張の強さの言葉

Lab OS 02章のコミットメントを、動詞で実装します。

コミットメント使える動詞
記述observed, measured, found
説明indicates, is consistent with, is controlled by（代替説明を潰した後で）
予測predicts, generalizes to
制御enables, improves, reduces

"suggests" は説明への弱いコミットメントとして Discussion でのみ使う。Results には使わない。"demonstrates" と "proves" は、証拠がそのレベルに届いているときだけ。

動詞のコミットメントは、証拠のレベルを超えない。

最終チェックリスト

1
書く順序は Methods → Results → Discussion → Introduction → Conclusion → Abstract か
2
Methods は他人が再現できる粒度か
3
Results は図と1対1で、解釈も評価語も "suggests" もないか
4
Discussion は5段落（Direct Answer / Gap Resolution / Assumption Refinement / Field Implication / Limitations）か
5
Discussion の最初の文、Introduction の Here we show、Conclusion の最初の文が一致しているか
6
Introduction の Gap は Discussion で回収されているか
7
Abstract は6〜7文・固定順・250 words 以内で、本文と一致しているか
8
想定 Reviewer コメント4つへの答えを、原稿の場所つきで言えるか
9
Writing Paper Skills の5項目を一文ずつ通したか
